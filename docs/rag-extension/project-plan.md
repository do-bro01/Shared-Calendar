## 2. 프로젝트 목표

1. **일정 + 사진 + 코멘트 데이터를 자연어로 검색하는 RAG 챗봇** 구현
2. **개인/그룹 단위 권한 격리 검색** (pgvector + RLS)
3. **RAGAS 기반 정량 평가** (Ground Truth 15개 이상)
4. **모바일·웹 통합 UI** 구현 (기존 React Native 앱 + Streamlit 데모)
5. **(가점)** RAG 성능 개선 기법 적용 (Hybrid Search, Re-ranking 등)

### 4.1 데이터 흐름 (수집)

1. 사용자가 일정/사진/코멘트 등록
2. Supabase Trigger 또는 Edge Function이 변경 감지
3. OpenAI Embedding API로 임베딩 생성 (텍스트 + 사진 캡션)
4. `embeddings` 컬럼/테이블에 저장

### 4.2 데이터 흐름 (검색)

1. 사용자가 챗봇에 자연어 질문 입력
2. Edge Function이 질문을 임베딩 변환
3. pgvector 유사도 검색 (RLS로 권한 격리 자동 적용)
4. 상위 K개 결과를 LLM 컨텍스트에 주입
5. LLM이 답변 생성 + 출처 정보 포함
6. 응답 + 검색된 청크 ID를 `chat_messages`에 저장 (Memory)

## 5. 기술 스택

| 영역                   | 선택                                                  | 이유                                            |
| ---------------------- | ----------------------------------------------------- | ----------------------------------------------- |
| **Frontend (메인)**    | React Native + Expo + react-native-web                | 기존 MVP 코드 재사용, 모바일/웹 동시 지원       |
| **Frontend (데모)**    | Streamlit                                             | 발표용 빠른 시각화, RAG 파이프라인 디버깅 UI    |
| **Backend**            | Supabase (Postgres + Auth + Storage + Edge Functions) | 기존 인프라 재사용, BaaS 비용 효율              |
| **Vector DB**          | Supabase pgvector                                     | 별도 벡터 DB 도입 불필요, RLS와 자연스럽게 결합 |
| **Embedding 모델**     | OpenAI `text-embedding-3-small` (1536차원)            | $0.02/M 토큰, 한국어 품질 양호                  |
| **LLM (생성)**         | Claude Haiku 4.5 또는 GPT-4o-mini                     | 비용 효율 + 한국어 우수, 챗봇용 충분            |
| **Vision (사진 캡션)** | Claude Sonnet Vision 또는 GPT-4o Vision               | 업로드 1회만 호출 (캐시)                        |
| **RAG 프레임워크**     | LangChain (Python)                                    | Edge Function 또는 별도 백엔드에서 사용         |
| **평가**               | RAGAS                                                 | 수업 요구사항                                   |
| **Re-ranking (가점)**  | Cohere Rerank API 또는 BGE-Reranker                   | 검색 정확도 향상                                |
| **배포**               | Vercel (RN 웹) + Streamlit Cloud (데모) + Supabase    | 무료 또는 저비용                                |
| **모니터링**           | Supabase Dashboard + LangSmith (옵션)                 | 호출 로그·비용 추적                             |

## 6. 주요 기능 (신규)

### 6.1 사진 업로드

- 일정 카드에서 사진 추가
- Supabase Storage에 저장
- 업로드 직후 Vision API로 캡션 자동 생성 → DB 저장 → 임베딩 생성

### 6.2 코멘트

- 일정에 멤버들이 코멘트 추가
- 작성 즉시 임베딩 생성
- 실시간 동기화 (Supabase Realtime)

### 6.3 챗봇 화면 (메인 신규)

- 자연어 입력
- 응답에 출처 일정 카드를 함께 표시
- 카드 탭 시 해당 일정 상세로 이동
- 대화 히스토리 좌측 사이드바

### 6.4 추억 피드 화면 (선택)

- 지난 일정 중 사진/코멘트가 있는 것만 시간순 표시
- LLM 월별 요약 노출

### 6.5 검색 범위 선택

- "내 데이터만" / "○○ 그룹"
- RLS와 함께 검색 쿼리에서 명시적 필터링

## 9. 평가 계획 (RAGAS)

### 9.1 Ground Truth 구성 (15개 이상)

| 분류                  | 개수 | 예시                                 |
| --------------------- | ---- | ------------------------------------ |
| 사실 기반 (날짜/장소) | 6    | "2025년 7월에 다녀온 여행지는?"      |
| 사실 기반 (인물/관계) | 3    | "엄마와 함께한 일정 중 가장 최근은?" |
| 통계/패턴             | 3    | "지난 1년 동안 가장 자주 간 식당은?" |
| 멀티모달 (사진 기반)  | 3    | "벚꽃 사진 찍은 날 어디였지?"        |

### 9.2 메트릭

| 메트릭            | 목표   | 측정 방법 |
| ----------------- | ------ | --------- |
| Faithfulness      | ≥ 0.85 | RAGAS     |
| Answer Relevancy  | ≥ 0.80 | RAGAS     |
| Context Precision | ≥ 0.75 | RAGAS     |
| Context Recall    | ≥ 0.80 | RAGAS     |

### 9.3 비교군

1. **Baseline**: 순수 LLM (전체 일정을 텍스트 dump해서 컨텍스트에 넣음)
2. **RAG Basic**: 단순 벡터 검색 + LLM
3. **RAG Advanced**: Hybrid Search (BM25 + Vector) + Re-ranking + LLM

각 비교군에 대해 동일한 Ground Truth로 정확도/응답시간/토큰비용 측정.
